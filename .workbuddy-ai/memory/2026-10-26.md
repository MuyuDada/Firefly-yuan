## 修复 /analytics 深色模式下文字发黑

**现象**：深色主题下统计页大量文字（卡片里的数字、说明、次要信息）仍是黑色，深色背景上几乎看不清。

**根因**：页面移植自 Aemeath 主题，全篇文字颜色写成
`color-mix(in oklab, var(--text-color) 92%, transparent)`，
但本项目根本没有 `--text-color` 这个变量。变量未定义 → `color-mix()` 整体无效 → `color` 属性失效 → 退化为继承，落在深色卡片里就是黑字。

**同类缺失变量**（一并补齐）：`--font-active-sans`、`--glass-control-border`。

**修复**（`src/pages/analytics.astro`）：
- 在 `.analytics-page` 作用域内显式定义 `--text-color: oklch(0.25 0.02 var(--hue))`，并在 `:root.dark .analytics-page` 覆盖为 `oklch(0.93 0.01 var(--hue))`，让文字随主题反转。
- 补 `--font-active-sans: inherit`、`--glass-control-border`（基于 `--line-divider`）。
- 把 `var(--deep-text)`（深色下不反转）改为 `var(--text-color)`。
- `AnalyticsSnapshot.astro` 同样补了 `--text-color` 兜底与深色覆盖。

**验证**：用无头浏览器读取 computed color，深色得到 `oklab(0.93 … / 0.92)`（浅色文字），亮色得到 `oklab(0.25 … / 0.92)`（深墨文字）。

**备注**：无头截图在本机不稳定，改用「注入探针脚本 + `--dump-dom` 读 `document.title`」的方式验证计算样式，比截图快且不会崩。

## 打通 Umami Cloud 真实数据

用户提供分享链接 `https://cloud.umami.is/share/GcPdaTVEckbxE6Zf`。

**关键发现**：`cloud.umami.is` 不是 API 域名，真实网关是 `https://gateway-us.umami.is`（通过 CDP 抓分享页 Network 请求确认）。路径格式与参考实现一致：
- `GET /api/share/{shareId}` → `{ websiteId, token }`
- `GET /api/websites/{websiteId}/stats|pageviews|metrics`，header 带 `x-umami-share-token` + `x-umami-share-context: 1`

**配置**：`shareApiBase: "https://gateway-us.umami.is"`，`shareId: "GcPdaTVEckbxE6Zf"`。同时把 `sourceLabel` 判断从 `includes("cloud.umami.is")` 改为 `includes("umami.is")`。

**补漏**：累计四张卡片（累计访客/浏览、今日访客/浏览）由 `src/components/analytics/UmamiMetrics.astro` 负责更新，首次移植时漏掉了这个组件，导致数字一直停在「加载中」。已补上并在 `analytics.astro` 中渲染传参。

**实测结果**：累计访客 222、累计浏览 1,466、今日访客 5、今日浏览 54，地域分布（广东 33.3% / 安徽 20.0% / 上海 13.3%）、设备与浏览器分布均正常。

**注意**：`shouldBlockLocalStats()` 在非 `/analytics` 路径的本地页面会把数字显示成「不统计」，这是刻意设计，不要误判为 bug。
