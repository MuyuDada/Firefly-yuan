## 环境坑（重要，后续复用）
- **本机所有浏览器进程都会被环境杀掉**（SIGTERM）：agent-browser、`chrome --headless=new` 截图均无法使用，**无法做视觉截图验证**。改用「Vite dev server 拉编译产物 + grep 类名」做静态验证。
- 本机存在代理 `HTTP_PROXY=http://127.0.0.1:14053` 且 `NO_PROXY` 为空，浏览器/CLI 访问 localhost 会走代理而挂起。
- 删除守卫 `safe-delete`：非 `node_modules`/`dist` 路径的批量删除会被转 `trash`，超过 50 个文件会失败并可能让守卫 **state lock 卡死**。绕过办法：`cmd //c "rd /s /q <dir>"`（实测可用）；`node fs.rmSync` 对 `node_modules` 下的路径可直接删。
- `pnpm build` / `pnpm dev` 首次会因守卫拦截 `dist/.prerender/.vite`、`node_modules/.vite/deps` 的批量删除而失败；先手动清 `node_modules/.vite` 再跑 dev 即可。
- Astro 路由为**尾斜杠**：`/music/` 才是 200，`/music` 是 404。
- 音乐页布局只在 `sceneReady` 后渲染（`MusicVisualizer.svelte` 里 `{#if sceneReady}`），所以无 WebGL 的环境即使截图也看不到控件。

## dev server 冲突排查（重要教训）
- 现象 1：浏览器预览报 `upstream connect failed ... os error 10061` → 代理转发到 4321 失败，说明 dev server 已退出。
- 现象 2：VS Code 里 `pnpm dev` 报 `Only one dev server is allowed / Acquire lock failed (PID 2244)` → 后台残留进程霸占锁。
- 根因：**AI 在后台起的 dev server 会与用户自己在 VS Code 里启动的冲突**。Astro 同项目只允许一个 dev server。
- 锁文件：`.astro/dev.json`（记录 `pid`/`port`/`startedAt`）。进程被 kill 后该文件**不会自动清除**，残留死 PID 会干扰下次启动判断。
- 清理步骤：① `TaskStop` 杀掉后台任务 → ② 确认 `tasklist //FI "PID eq <pid>"` 无该进程、`netstat -ano | grep :4321` 无 LISTENING → ③ `rm -f .astro/dev.json`。
- 结论：**以后不要让 AI 在后台长驻 dev server**；需要预览时起、用完即停；用户要自己跑时先确保锁已释放。
- 另注：Astro dev 只监听 IPv6 `[::1]:4321`，`curl http://127.0.0.1:4321` 会失败（HTTP 000），必须用 `localhost` 或 `[::1]`。
