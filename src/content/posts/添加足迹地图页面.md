博客写久了，总想有点「人味儿」的东西——不是文章列表，不是标签云，而是**我去过哪儿**。

足迹页就是干这个的：一页地图，每个去过的地方一个点，点开是一条记录——什么时候去的、待了几天、在那儿干了什么、有没有照片。数据全放在 Markdown 里，跟写文章一样。

这篇记录完整的落地过程：从申请地图 Key 到写下第一条足迹，包括几个我踩过的坑。

## 一、成品是什么样

页面分两栏：左边地图，右边列表。具体能力：

- **自动打点** — 坐标不需要精确到门牌，写了就按写的画，没写就用省市中心兜底
- **点位聚合** — 同一座城市去过五六次，点位会挤在一起，所以按像素网格自动聚合成一个带数字的圆
- **年份 / 分类筛选** — 2021、2022… 或者「旅游 / 学校 / 工作」
- **点击弹卡片** — 站名、日期、经历、照片轮播，不跳页
- **顶部统计胶囊** — 城市数、省份数、到访次数、今年去过几处
- **常驻位置红点** — 地图上单独标出你现在住哪儿，跟足迹区分开

## 二、三步装好

### 第 1 步：打开页面和导航

页面本身在 `src/pages/places.astro`，默认是关掉的。两个开关都要开：

```ts
// src/config/siteConfig.ts
pages: {
  places: true,   // 打开 /places/ 页面
  // ...
}
```

导航项是预置好的，在 `src/config/navBarConfig.ts` 的「我的」子菜单里：

```ts
children: [
  LinkPresets.Dynamic,
  LinkPresets.Projects,
  LinkPresets.Devices,
  LinkPresets.Places,   // ← 足迹地图
  LinkPresets.Gallery,
],
```

把它从数组里删掉，导航里就不会出现入口（页面还能直接访问）。反过来，`pages.places` 关掉时访问 `/places/` 会直接重定向到 404——这是我故意的，避免页面存在但没数据。

### 第 2 步：申请高德 Key

足迹地图用的是**高德 JS API 2.0**，需要两样东西：

1. **Key** — 控制台 → 应用管理 → 创建应用 → 添加 Key，服务平台选「**Web端(JS API)**」
2. **安全密钥** — JS API 2.0 起强制要求，跟 Key 配套生成

申请地址：https://console.amap.com/dev/key/app

拿到之后有两个地方可以填，**推荐用环境变量**：

```bash
# .env（不进仓库）
PUBLIC_AMAP_KEY=你的Key
PUBLIC_AMAP_SECURITY_CODE=你的安全密钥
```

代码里的优先级是「环境变量 > 配置文件」：

```ts
// src/pages/places.astro
const amapKey = (
  import.meta.env.PUBLIC_AMAP_KEY ||
  mapConfig.amapKey ||
  ""
).trim();
```

之所以优先环境变量：Key 虽然最终会出现在前端代码里（这是 JS API 的机制，藏不住），但至少不用把它写进公开仓库。

> **一定要配域名白名单。** 高德控制台里把这个 Key 绑定到你的域名，否则别人拿了 Key 就能刷你的配额。前端可见的凭证只能靠白名单保护。

**没配 Key 会怎样？** 地图区域显示一行配置提示，右边的列表和统计照常工作。所以你可以先不做地图、只当「足迹清单」用。

### 第 3 步：写下第一条足迹

数据放在 `src/content/places/`，**一个 md 记一次到访**。文件名随便起，建议 `城市-地点.md`：

```md
---
name: 故宫博物院
date: 2025-10-02
province: 北京
city: 北京
district: 东城区
experience: 国庆假期 · 从午门一路走到神武门，中轴线比想象中更长
visitCount: 1
category: 旅游
lng: 116.3972
lat: 39.9163
images:
  - https://你的图床/故宫1.webp
  - https://你的图床/故宫2.webp
---

正文写不写都行，页面上只读 frontmatter。
```

保存，`pnpm dev` 里刷新 `/places/`，点就上去了。

## 三、字段逐条说清楚

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | ✅ | 到访日期，`2025-10-02` 这样写 |
| `province` | ✅ | 省份，**要和兜底坐标表里的写法一致**（见下文） |
| `endDate` | | 结束日期，跨天行程填上，年份筛选会覆盖这段区间 |
| `name` | | 具体地点名；不填则依次回落到 区 → 市 → 省 |
| `city` | | 城市，不填就只按省算 |
| `district` | | 区县，只影响显示名，不影响坐标 |
| `experience` | | 一句话经历。**它决定了分类推断**，下面细说 |
| `visitCount` | | 到访次数，默认 1。影响点位上的数字和顶部「到访次数」统计 |
| `category` | | 分类。不写就按 `experience` 推断 |
| `lat` / `lng` | | 精确坐标（高德坐标系）。不写用省市中心 |
| `images` | | 照片数组，点击点位时轮播。不写就是纯文字卡片 |
| `link` | | 外链，有的话卡片底部多一个「查看详情」 |

## 四、坐标：能不给就别给

`lat` / `lng` 是可选的。**不填，页面会用省市中心坐标兜底**——数据来自 `src/data/china-city-coords.ts`，覆盖了国内主要城市。

只有一种情况值得填精确坐标：你想让点位落在具体位置（比如「故宫」在北京市中心偏北），或者同一座城市有多个点需要拉开距离。

填的话有几个规矩：

1. **必须是 GCJ-02 坐标**（高德、腾讯用的火星坐标系）。从 GPS 设备或 Google Maps 拿到的 WGS84 坐标直接填，会偏几百米
2. 用高德的官方拾取工具最省事：https://lbs.amap.com/tools/picker —— 在地图上点一下，复制出来的就是 GCJ-02
3. **省市名要和 `china-city-coords.ts` 里的键一致**。写「北京市」而表里是「北京」，兜底就查不到，那个点会消失（且不报错）

第 3 点是最容易踩的坑。加完新省份后，建议回头看一眼那个文件，确认键名对得上。

## 五、分类不用手写，但可以覆盖

`category` 是筛选用的一排胶囊。不写的时候按 `experience` 里的关键词推断：

```ts
// src/utils/places-utils.ts
if (place.category?.trim()) return place.category.trim();
if (SCHOOL_RE.test(text)) return "学校";
if (WORK_RE.test(text)) return "工作";
return "旅游";
```

也就是说：

- 经历里提到「上学 / 毕业 / 宿舍」→ **学校**
- 提到「入职 / 实习 / 加班」→ **工作**
- 其余一律 **旅游**

手写的优先级最高。要是你想细分「出差」「探亲」，直接写 `category: 出差` 就行，胶囊会跟着长出来——不需要改代码。

## 六、统计是怎么算的

顶部那四个数字不是写死的，每次构建时从所有 md 里算：

```ts
locations  = (province|city) 去重后的数量   // 「城市数」
provinces  = province 去重后的数量          // 「省份数」
visits     = visitCount 累加                // 「到访次数」
thisYear   = date..endDate 覆盖今年的条数   // 「今年」
```

所以同城打卡十次，`locations` 还是 1，但 `visits` 是 10，这俩口径不一样。

## 七、几个坑

**1. `images` 写了但全被注释掉，构建直接失败**

```yaml
images:
  # - https://...
```

YAML 会把它解析成 `null`，`z.array()` 校验不过，整个站点构建报错。所以 schema 里加了兜底：

```ts
images: z.preprocess(
  (value) => (value === null || value === undefined ? [] : value),
  z.array(z.string()),
),
```

如果你是从别的主题抄的字段，注意看看有没有这层保护。

**2. 同城多个点会叠在一起**

北京的五个点如果都用省市中心兜底，坐标完全一样，画出来就是一个点。解法有两个：填精确坐标，或者靠聚合——页面用像素网格自己做聚合，放大到一定级别后自动散开。

**3. 没用官方的 `AMap.MarkerCluster` 插件**

高德 2.0 的聚合插件只认数据点，而且会强行用它的蓝色默认图标。为了保持自定义样式，这里是**自己管 Marker、自己算像素网格**做聚合，代价是多写了一百多行，好处是图标、数字角标、点击行为都能完全控制。

**4. 新增足迹要重新部署**

内容集合是**构建时读取**的，`src/content/places/*.md` 加了一条，本地 `pnpm dev` 立刻能看到，线上却要等下一次构建。

这也是静态站的通病——顺带一提，我这次还顺手把日历页的「今天」从构建时改成了浏览器运行时计算，不然页面缓存久了会一直显示构建那天。

## 八、小结

整套设计的取舍很明确：

- **数据用 Markdown** — 加一条足迹的成本和写一条笔记差不多，不需要数据库、不需要后台
- **坐标可以偷懒** — 只写省市也能出图，想精确再补
- **地图 Key 走环境变量** — 仓库里不留凭证，泄露风险靠域名白名单兜

如果你也做过「去过哪儿」的记录，从 `src/content/places/` 里那条故宫开始抄就行，改改字段值就是自己的了。
