博客里最容易被忽略、又最能提升"手感"的，往往不是排版，而是鼠标和键盘的反馈。这篇文章记录我给 Firefly 加上四种交互特效的完整过程：**自定义光标**、**点击粒子**、**星尘拖尾**和**输入火焰**。

最初我拿到的是一个现成的 HTML 片段，里面直接引了两段 CDN 脚本。能用，但不太适合长期放在博客里——下面会讲为什么最终选择重写。

## 一、功能概览

四个特效各司其职，互不干扰：

| 特效 | 触发方式 | 效果 |
| --- | --- | --- |
| 自定义光标 | 鼠标移动 | 一个半透明圆点缓动跟随，悬停可点击元素时放大变淡，按下时缩小变实 |
| 点击粒子 | 单击 / 长按 | 从点击位置迸发彩色小球，长按 500ms 后抬起会迸发更多、更快的小球 |
| 星尘拖尾 | 鼠标移动 | 指针后方洒落星形粒子，边下落边缩小淡出 |
| 输入火焰 | 输入框打字 | 从光标位置迸出向上飘散的粒子 |

四个特效全部接入设置面板的「特效」标签页，可以随时开关，**切换即时生效，不需要刷新页面**。

## 二、实现细节

### 为什么不用现成脚本

拿到的原始片段是这样加载的：

```html
<script src="https://cdn.jsdelivr.net/gh/huangwb8/bloghelper@latest/js/input-with-fire.js"></script>
<script src="https://cdn.jsdelivr.net/gh/huangwb8/bloghelper@latest/mouse/halo-dream/fairyDustCursor.min.js"></script>
```

三个问题让我决定重写：

1. **`@latest` 是供应链风险**。这个标签意味着上游仓库任何一次提交都会立即生效在你的博客上，没有任何版本锁定，也没有 SRI 校验。一旦对方仓库被删或被改，你的博客就白屏一块。
2. **Firefly 用 Swup 做无刷新切页**。Swup 只替换指定的容器，`document.body` 上挂载的元素会**跨页面存活**。直接跑两遍脚本就会叠出两个 canvas、两个光标。
3. **Firefly 已经有一整套特效架构**。`src/config/effectsConfig.ts` 配置 → `src/types/effectsConfig.ts` 类型 → `src/utils/setting-utils.ts` 读写 → 组件 → 设置面板 → i18n。把特效接进这条链路，用户才能在设置面板里开关它。

所以做法是：**保留算法，重写实现**，把它变成 Firefly 原生的四个组件。

### 统一的架构

新增的每个特效都遵循同一套模式，先看数据流：

```
effectsConfig.ts  ──►  setting-utils.ts  ──►  XxxEffect.astro
  （默认值）            （localStorage +       （读取状态并启动）
                        data-* 属性 +
                        CustomEvent）
                              │
                              ▼
                  DisplaySettingsIntegrated.svelte
                     （开关按钮 → 派发事件）
```

`src/utils/setting-utils.ts` 里新增了一对通用辅助函数，四个特效共用：

```typescript title="src/utils/setting-utils.ts"
/** 通用读取：localStorage 无值时回退到配置默认值 */
function readStoredToggle(key: string, fallback: boolean): boolean {
	if (
		typeof localStorage === "undefined" ||
		typeof localStorage.getItem !== "function"
	) {
		return fallback;
	}
	const stored = localStorage.getItem(key);
	return stored === null ? fallback : stored === "true";
}

/** 通用写入：落盘 + 同步 data-* 属性 + 广播切换事件 */
function writeStoredToggle(
	key: string,
	attr: string,
	eventName: string,
	enabled: boolean,
): void {
	if (
		typeof localStorage === "undefined" ||
		typeof localStorage.setItem !== "function"
	) {
		return;
	}
	localStorage.setItem(key, String(enabled));
	document.documentElement.setAttribute(attr, String(enabled));
	window.dispatchEvent(new CustomEvent(eventName, { detail: { enabled } }));
}
```

这里三个动作缺一不可：

- **写 localStorage**：刷新后记住用户选择；
- **写 `data-*` 属性**：CSS 可以据此调整样式（后面讲原生光标时会用到）；
- **派发 CustomEvent**：已经挂载的特效组件收到事件后实时启停，不用刷新。

四个特效的键名、属性名和事件名：

| 特效 | localStorage | `data-*` 属性 | 事件 |
| --- | --- | --- | --- |
| 自定义光标 | `cursorEnabled` | `data-cursor-enabled` | `cursorToggle` |
| 点击粒子 | `clickParticleEnabled` | `data-click-particle-enabled` | `clickParticleToggle` |
| 星尘拖尾 | `fairyDustEnabled` | `data-fairy-dust-enabled` | `fairyDustToggle` |
| 输入火焰 | `inputFireEnabled` | `data-input-fire-enabled` | `inputFireToggle` |

组件侧的入口都长这样，`window.__fireflyXxxInitialized` 守卫是应对 Swup 切页重跑脚本的关键：

```typescript title="src/components/features/ClickParticleEffect.astro"
(function setupClickParticle() {
	if (window.__fireflyClickParticleInitialized) return;
	window.__fireflyClickParticleInitialized = true;

	const manager = new ClickParticleManager();
	window.clickParticleManager = manager;

	const stored = localStorage.getItem("clickParticleEnabled");
	const enabled =
		stored === null ? clickParticleConfig.enable : stored === "true";

	if (enabled) {
		manager.init();
	}

	window.addEventListener("clickParticleToggle", (e: Event) => {
		const detail = (e as CustomEvent<{ enabled: boolean }>).detail;
		if (detail?.enabled) {
			manager.init();
		} else {
			manager.stop();
		}
	});
})();
```

### 自定义光标：缓动跟随与事件委托

缓动跟随本身很简单——每帧把当前位置朝目标位置推进一个系数：

```typescript title="src/components/features/CursorEffect.astro"
/** 每帧把当前位置朝目标位置推进 lerpFactor,形成缓动跟随 */
private render = (): void => {
	if (!this.isRunning) return;

	const k = cursorConfig.lerpFactor;
	this.currentX += (this.targetX - this.currentX) * k;
	this.currentY += (this.targetY - this.currentY) * k;

	if (this.root) {
		this.root.style.transform = `translate3d(${this.currentX}px, ${this.currentY}px, 0)`;
	}

	this.animationId = requestAnimationFrame(this.render);
};
```

真正值得说的是两个容易踩的坑。

**坑一：缩放和位移不能写在同一个元素上。** 如果外层元素既要 `translate` 又要 `scale`，两者会互相覆盖。所以拆成两层——外层只负责位移，内层负责缩放和透明度过渡：

```css title="src/styles/mouse.css"
#firefly-cursor {
	position: fixed;
	top: 0;
	left: 0;
	z-index: var(--firefly-cursor-z, 10086);
	pointer-events: none;
	opacity: 0;
	transition: opacity 200ms ease;
	will-change: transform;
}

.firefly-cursor-dot {
	width: var(--firefly-cursor-size, 20px);
	height: var(--firefly-cursor-size, 20px);
	margin: calc(var(--firefly-cursor-size, 20px) / -2);
	border-radius: 50%;
	background: var(--firefly-cursor-color, rgb(57, 197, 187));
	opacity: var(--firefly-cursor-opacity, 0.25);
	transition:
		opacity 200ms ease-in-out,
		transform 200ms ease-in-out;
}
```

**坑二：判断"是否悬停在可点击元素上"不要用 `elementsFromPoint`。** 那需要每帧查询，滚动和移动时都会触发强制布局。改用 `pointerover` / `pointerout` 事件委托——这两个事件会冒泡，只需在 `window` 上各挂一个监听器：

```typescript title="src/components/features/CursorEffect.astro"
// 用事件委托判定悬停:pointerover/out 会冒泡,无需给每个元素绑事件
this.boundHandleOver = (e: PointerEvent) => {
	const target = e.target as Element | null;
	if (target?.closest?.(INTERACTIVE_SELECTOR)) {
		this.root?.classList.add("is-hover");
	}
};

this.boundHandleOut = (e: PointerEvent) => {
	const target = e.target as Element | null;
	const related = e.relatedTarget as Element | null;
	// 只有当移出的元素本身可交互、且移入的元素不再可交互时才取消悬停
	if (
		target?.closest?.(INTERACTIVE_SELECTOR) &&
		!related?.closest?.(INTERACTIVE_SELECTOR)
	) {
		this.root?.classList.remove("is-hover");
	}
};
```

注意 `pointerout` 里必须同时检查 `relatedTarget`。否则在按钮内部的图标和文字之间移动时，会先触发 `out` 再触发 `over`，光标闪烁一下。

### 原生光标：留一条后路

把原生光标完全隐藏（`cursor: none`）是有风险的：万一 JS 报错没执行，用户会**完全看不到光标**，只能靠猜。

所以配置里给了三种模式：

```typescript title="src/types/effectsConfig.ts"
export type NativeCursorMode = "dot" | "none" | "default";
```

- `dot`（默认）：用一个 8×8 的半透明 SVG 圆点替换原生光标。即使自定义光标没起来，用户仍能看到一个可见的落点；
- `none`：完全隐藏，视觉最干净；
- `default`：保留原生光标，两个光标同时存在。

`dot` 模式的实现是纯 CSS，靠 `data-cursor-enabled` 属性开关：

```css title="src/styles/mouse.css"
/* nativeCursor = "dot"：用半透明小圆点替换原生光标 */
/* 好处是即使 JS 执行失败，用户依然能看到一个可见光标，不会「找不到鼠标」。 */
html[data-cursor-enabled="true"][data-native-cursor="dot"],
html[data-cursor-enabled="true"][data-native-cursor="dot"] body,
html[data-cursor-enabled="true"][data-native-cursor="dot"] * {
	cursor:
		url("data:image/svg+xml,%3Csvg%20xmlns='http://www.w3.org/2000/svg'%20viewBox='0%200%208%208'%20width='8'%20height='8'%3E%3Ccircle%20cx='4'%20cy='4'%20r='4'%20opacity='0.5'/%3E%3C/svg%3E")
		4 4,
		auto;
}
```

但还要把可点击元素的手型光标加回来，否则会削弱"这里能点"的提示：

```css title="src/styles/mouse.css"
html[data-cursor-enabled="true"][data-native-cursor="dot"]
	:is(
		a,
		button,
		input[type="button"],
		input[type="submit"],
		input[type="reset"],
		select,
		label,
		summary,
		[role="button"],
		[role="link"],
		.cursor-pointer
	) {
	cursor: pointer;
}
```

### 点击粒子：长按判定与粒子回收

粒子系统最怕内存泄漏。这里的粒子有两个消亡条件——半径衰减到 0，或者飞出视口，两者任一满足就**原地 splice 移除**：

```typescript title="src/components/features/ClickParticleEffect.astro"
// 出界或缩没了的粒子直接移除,避免数组无限增长
if (
	ball.radius <= 0 ||
	ball.x < -50 ||
	ball.x > width + 50 ||
	ball.y < -50 ||
	ball.y > height + 50
) {
	this.balls.splice(i, 1);
	continue;
}
```

注意循环是**从后往前**遍历的（`for (let i = this.balls.length - 1; i >= 0; i--)`）。倒序遍历时 `splice` 不会跳过下一个元素，这是删除数组元素的标准做法。

长按判定用计时器而不是时间戳比较，逻辑更直观：按下时起一个 500ms 的定时器，到点把 `isLongPress` 标为 `true`；抬起时按这个标志选择参数：

```typescript title="src/components/features/ClickParticleEffect.astro"
// 长按用更大的数量与初速度,单击用默认值
const { count, speed } = this.isLongPress
	? clickParticleConfig.longPress
	: clickParticleConfig;
this.spawn(
	e.clientX,
	e.clientY,
	randomIntBetween(count.min, count.max),
	speed.min,
	speed.max,
);
```

### 星尘拖尾：预渲染字形

这个特效最大的性能陷阱是**逐帧 `fillText`**——每帧都要把字符重新栅格化一次，粒子一多立刻掉帧。

解法是每种颜色只画一次，把结果存成离屏 canvas，运行时只做 `drawImage` 缩放：

```typescript title="src/components/features/FairyDustEffect.astro"
/**
 * 把字形预渲染到一张刚好包住它的离屏 canvas。
 * 尺寸用 measureText 的宽度 + 实际上下沿(ascent/descent)计算,
 * 避免留白导致绘制位置偏移。
 */
private renderGlyph(color: string): HTMLCanvasElement {
	const { glyph, fontSize } = fairyDustConfig;

	const canvas = document.createElement("canvas");
	const ctx = canvas.getContext("2d");
	if (!ctx) return canvas;

	const font = `${fontSize}px serif`;
	ctx.font = font;
	ctx.textAlign = "center";
	ctx.textBaseline = "middle";

	const metrics = ctx.measureText(glyph);
	const width = Math.ceil(metrics.width) || fontSize;
	const height = Math.ceil(
		(metrics.actualBoundingBoxAscent || fontSize * 0.5) +
			(metrics.actualBoundingBoxDescent || fontSize * 0.5),
	);

	canvas.width = width;
	canvas.height = height;

	// 改过尺寸后 canvas 上下文会重置,需重新设置样式再绘制
	ctx.font = font;
	ctx.textAlign = "center";
	ctx.textBaseline = "middle";
	ctx.fillStyle = color;
	ctx.fillText(glyph, width / 2, height / 2);

	return canvas;
}
```

这里有个隐藏的坑：**`canvas.width = ...` 会重置整个 2D 上下文状态**。所以设置尺寸之后必须重新设置 `font`、`textAlign`、`fillStyle`，否则第二次绘制就是默认样式。

另外，鼠标静止或轻微抖动时不应该持续生成粒子，用移动距离做个阈值：

```typescript title="src/components/features/FairyDustEffect.astro"
// 移动距离太小时不生成,鼠标静止或微抖不会堆积粒子
const distance = Math.hypot(x - this.lastX, y - this.lastY);
if (distance < fairyDustConfig.minDistance) return;
```

### 输入火焰：镜像 div 测量光标位置

这是四个特效里技术含量最高的一个。要在输入框里精确定位光标，浏览器**没有**提供现成 API，得用"镜像元素"这个经典技巧：

造一个与输入框样式**完全一致**的隐藏 div，把光标之前的文本塞进去，末尾追加一个 `<span>`，那么 span 的 `offsetLeft` / `offsetTop` 就是光标相对输入框内容区的位置。

```typescript title="src/components/features/InputFireEffect.astro"
/** 镜像 div 需要复制的样式属性,漏掉任何一项都会让光标位置算偏 */
const MIRRORED_STYLES = [
	"direction",
	"boxSizing",
	"width",
	"height",
	"overflowX",
	"overflowY",
	"borderTopWidth",
	"borderRightWidth",
	"borderBottomWidth",
	"borderLeftWidth",
	"borderStyle",
	"paddingTop",
	"paddingRight",
	"paddingBottom",
	"paddingLeft",
	"fontStyle",
	"fontVariant",
	"fontWeight",
	"fontStretch",
	"fontSize",
	"fontSizeAdjust",
	"lineHeight",
	"fontFamily",
	"textAlign",
	"textTransform",
	"textIndent",
	"textDecoration",
	"letterSpacing",
	"wordSpacing",
	"tabSize",
	"MozTabSize",
] as const;
```

**这里有个非常隐蔽的坑：`getPropertyValue()` 只认 kebab-case。** 上面这个数组为了能直接写 `computed.fontSize` 用的是 camelCase，但 `CSSStyleDeclaration.getPropertyValue()` 按 CSS 属性名规范取值，传 camelCase 会**静默返回空字符串**——不报错、不警告：

```typescript
// ❌ 错误写法:getPropertyValue 不认 camelCase,每一项都返回 ""
for (const prop of MIRRORED_STYLES) {
	mirror.style[prop as unknown as number] = computed.getPropertyValue(prop);
}
```

实测结果（导航栏搜索框，`pl-10 text-sm`）：

| 属性 | `getPropertyValue("fontSize")` | `computed["fontSize"]` |
| --- | --- | --- |
| `fontSize` | `""` | `"14px"` |
| `paddingLeft` | `""` | `"40px"` |
| `boxSizing` | `""` | `"border-box"` |
| `lineHeight` | `""` | `"normal"` |

于是镜像既丢了 `padding-left: 40px`，字体又退回浏览器默认的 `16px`，量出来的光标位置整体偏左约 36px。**这是纯水平方向的偏差**——所以只修垂直方向的公式根本治不好它。

正确写法是先转 kebab-case，并且写内联样式也用 `setProperty`（避免 camelCase 索引在部分属性上失效）：

```typescript title="src/components/features/InputFireEffect.astro"
/** camelCase → kebab-case，供 getPropertyValue/setProperty 使用 */
function toKebabCase(prop: string): string {
	return prop.replace(/[A-Z]/g, (match) => `-${match.toLowerCase()}`);
}

// 注意:必须转成 kebab-case 再取/设值,getPropertyValue 不认 camelCase。
for (const prop of MIRRORED_STYLES) {
	const kebab = toKebabCase(prop);
	mirror.style.setProperty(kebab, computed.getPropertyValue(kebab));
}
```

改完后实测：镜像字体 `14px`、`padding-left: 40px`，量出的 x 与浏览器真实文字位置（用 canvas `measureText` 独立算出的真值）只差 **0.16px**，修复前则差 **35.84px**。

测量完立刻移除镜像节点，不常驻 DOM：

```typescript title="src/components/features/InputFireEffect.astro"
// 输入框有滚动时,镜像也要减掉相同偏移
const scrollTop = el.scrollTop;
const scrollLeft = el.scrollLeft;

const caretText = el.value.substring(0, el.selectionEnd ?? 0);
mirror.textContent = caretText;

const marker = document.createElement("span");
marker.textContent = el.value.substring(el.selectionEnd ?? 0) || ".";
mirror.appendChild(marker);

document.body.appendChild(mirror);

const borderTop = Number.parseFloat(computed.borderTopWidth) || 0;
const borderLeft = Number.parseFloat(computed.borderLeftWidth) || 0;

const rect = el.getBoundingClientRect();

// 水平位置两种输入框都一样:镜像里 span 的 offsetLeft 即光标相对内容区左侧的距离。
const x = rect.left + marker.offsetLeft + borderLeft - scrollLeft;

let y: number;
if (isTextarea) {
	// 多行文本域:行位置由镜像给出,顶部对齐
	y = rect.top + marker.offsetTop + borderTop - scrollTop;
} else {
	// 单行 input 的文字始终在内容区里垂直居中(导航栏搜索框 h-11 就靠这个居中),
	// 而镜像的 height 被复制成了输入框的固定高度,量不出真实行高。
	// 这里直接取内容区中线,既准确又不受固定高度影响。
	const paddingTop = Number.parseFloat(computed.paddingTop) || 0;
	const paddingBottom = Number.parseFloat(computed.paddingBottom) || 0;
	const contentHeight = el.clientHeight - paddingTop - paddingBottom;
	y = rect.top + borderTop + paddingTop + contentHeight / 2;
}

mirror.remove();
```

**单行 `input` 必须单独处理垂直位置。** 这是我在导航栏搜索框上踩到的坑：多行 `textarea` 的文字从内容区顶部开始排，用 `marker.offsetTop` 是对的；但单行 `input` 的文字被浏览器**垂直居中**在内容区里，而镜像 `div` 因为是块级元素、文字贴顶排，`offsetTop` 恒为 0。导航栏搜索框是 `h-11`（44px 高）而文字只有 14px，两者差了约 15px——火焰会明显飘在光标上方。

更麻烦的是镜像没法直接量出这个差值：`MIRRORED_STYLES` 里复制了 `height`，镜像被撑成和输入框一样的 44px，`offsetHeight` 量到的还是 44px 而不是真实行高。与其绕开这个循环依赖，不如直接用公式算——单行输入框的光标位置**必然**在内容区中线上：

```
内容区高度 = clientHeight − paddingTop − paddingBottom
y = rect.top + borderTop + paddingTop + 内容区高度 / 2
```

`clientHeight` 包含 padding 但不含 border，所以要先把 padding 减掉得到纯内容高度，再加回 `borderTop + paddingTop` 换回视口坐标。

`contenteditable` 区域走另一条路——用 `Selection` 的 `Range` 包围盒。但光标是**折叠**的（宽高为 0），直接取矩形会得到全零，所以要临时插入一个零宽字符来"撑开"位置：

```typescript title="src/components/features/InputFireEffect.astro"
// contenteditable 等场景:用选区的包围盒
const selection = window.getSelection();
if (selection && selection.rangeCount > 0) {
	const range = selection.getRangeAt(0).cloneRange();
	// 光标是折叠的(range 宽高为 0),插入一个临时节点量出位置
	const marker = document.createElement("span");
	marker.textContent = "\u200b";
	range.insertNode(marker);
	const rect = marker.getBoundingClientRect();
	const parent = marker.parentNode;
	parent?.removeChild(marker);
	// 合并相邻文本节点,避免反复插入节点把 DOM 切碎
	parent?.normalize?.();
	return { x: rect.left, y: rect.top };
}
```

`normalize()` 那行很重要：每次输入都插入再删除一个节点，会把文本切成一堆碎片，长期打字后 DOM 会变得非常臃肿。

粒子用**环形缓冲区**管理，上限 500 个，满了就覆盖最旧的，避免频繁 push/splice 造成 GC 抖动：

```typescript title="src/components/features/InputFireEffect.astro"
/** 环形缓冲区容量:超出后覆盖最旧的粒子,避免数组无限增长 */
const MAX_PARTICLES = 500;
```

### 无障碍与性能

三个共同的处理：

**触屏设备和"减少动效"偏好下完全不启动。** 这既是无障碍要求，也避免了在手机上白白消耗电量：

```typescript
if (
	window.matchMedia("(pointer: coarse), (prefers-reduced-motion: reduce)")
		.matches
) {
	return;
}
```

**canvas 按 DPR 放大，再用 `setTransform` 拉回 CSS 像素。** 用 `setTransform` 而不是 `scale`，因为 resize 会被反复触发，`scale` 会累乘缩放系数：

```typescript title="src/components/features/ClickParticleEffect.astro"
/** 按 DPR 放大 canvas 像素尺寸,再用 setTransform 把绘制坐标拉回 CSS 像素 */
private resize = (): void => {
	const canvas = this.canvas;
	const ctx = this.ctx;
	if (!canvas || !ctx) return;

	const dpr = window.devicePixelRatio || 1;
	const w = window.innerWidth;
	const h = window.innerHeight;

	canvas.width = w * dpr;
	canvas.height = h * dpr;
	canvas.style.width = `${w}px`;
	canvas.style.height = `${h}px`;

	// setTransform 而非 scale:重复 resize 时不会累乘缩放系数
	ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
};
```

**所有指针事件都用 `{ passive: true }`。** 这些监听器只是"看一眼"事件，不调用 `preventDefault()`，声明被动能让浏览器不用等待 JS 就能继续滚动：

```typescript
window.addEventListener("pointermove", this.boundHandleMove, {
	passive: true,
});
```

// 自定义光标（跟随鼠标的缓动圆点）

### 设置面板开关

`DisplaySettingsIntegrated.svelte` 的「特效」标签页里，每个特效就是一个按钮加一个胶囊开关：

```svelte title="src/components/controls/DisplaySettingsIntegrated.svelte"
{#if isCursorSwitchable}
<button
	class="w-full btn-regular rounded-md py-2 px-3 flex items-center gap-3 text-left active:scale-95 transition-all relative overflow-hidden"
	class:bg-(--btn-regular-bg-hover)={cursorEnabled}
	onclick={toggleCursorEnabled}
>
	<Icon icon="mdi:cursor-default-click-outline" class="text-[1.25rem] shrink-0"></Icon>
	<span class="text-sm flex-1">{i18n(I18nKey.customCursor)}</span>
	<div class="w-10 h-5 rounded-full transition-all duration-200 relative"
		 class:bg-(--primary)={cursorEnabled}
		 class:bg-(--btn-regular-bg-active)={!cursorEnabled}>
		<div class="absolute top-0.5 w-4 h-4 bg-white rounded-full shadow transition-all duration-200"
			 class:left-0.5={!cursorEnabled}
			 class:left-5={cursorEnabled}></div>
	</div>
</button>
{/if}
```

因为四个开关共用一个"恢复默认"按钮，判断条件要把它们全部算上：

```svelte title="src/components/controls/DisplaySettingsIntegrated.svelte"
// 特效设置里任意一项与默认值不同即显示"恢复默认"按钮
const hasEffectSettingChanged = $derived(
	(isCursorSwitchable && cursorEnabled !== defaultCursorEnabled) ||
		(isClickParticleSwitchable &&
			clickParticleEnabled !== defaultClickParticleEnabled) ||
		(isFairyDustSwitchable && fairyDustEnabled !== defaultFairyDustEnabled) ||
		(isInputFireSwitchable && inputFireEnabled !== defaultInputFireEnabled) ||
		(isSakuraSwitchable && sakuraEnabled !== defaultSakuraEnabled),
);
```
