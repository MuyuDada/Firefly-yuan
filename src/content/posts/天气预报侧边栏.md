天气预报侧边栏大概是博客里最"有温度"的小组件之一——每次打开首页，右侧栏顺手告诉你所在城市此刻的温度、天气，还有体感、湿度、风力和空气质量。Firefly 本身没有内置这个组件，本文记录从零实现一个完整天气卡片的全过程：数据来自免费的 [UAPI 天气接口](https://uapis.cn/docs/api-reference/get-misc-weather)，无需注册即可使用，默认按访客 IP 自动定位；访客额度被限流时可选用 API Key 兜底。

## 一、功能概览

![天气预报侧边栏组件](https://muyuimg.cc.cd/file/blog/Jw0d5PTd.webp)

主要能力：

- **三种定位方式** — 不传参数时按访客 IP 自动定位；也可传城市名 `city`（中英文皆可）或行政区划码 `adcode`（优先级最高）
- **基础天气** — 城市/区县、天气图标、当前温度、天气描述、最高/最低温、风力风向、湿度、更新时间
- **扩展气象**（`extended=true`）— 体感温度、能见度、气压、紫外线、云量、降水量、降水概率、空气质量指数与等级、PM2.5/PM10/O₃/NO₂/SO₂/CO 污染物分项、日出日落
- **本地缓存** — 结果缓存 30 分钟，减少接口请求
- **限流兜底** — 访客额度优先；被限流（HTTP 429）且配置了 API Key 时自动带 Key 重试一次
- **三态 UI** — 加载中 / 加载失败（带重试按钮）/ 数据展示
- **卡片能力** — 基于 `WidgetLayout` 开发，自动继承折叠与入场动画，亮暗色自适应

组件基于 `WidgetLayout` 卡片开发，效果可以直接看本站首页右侧栏。

<script>
	(function () {
		const API_URL = "https://uapis.cn/api/v1/misc/weather?";

		const CACHE_KEY = "weather_data_cache";
		const CACHE_TTL = 30 * 60 * 1000;

		// ✅ 修复：按需加载 Iconify 运行时（用于动态切换天气图标）
		function ensureIconifyLoaded() {
			if (typeof customElements !== "undefined" && customElements.get("iconify-icon")) {
				return Promise.resolve();
			}
			if (window.__iconifyLoading) return window.__iconifyLoading;
			window.__iconifyLoading = new Promise((resolve) => {
				const s = document.createElement("script");
				s.src = "https://code.iconify.design/iconify-icon/2.1.0/iconify-icon.min.js";
				s.onload = () => resolve();
				s.onerror = () => resolve(); // 加载失败也不阻塞其他逻辑
				document.head.appendChild(s);
			});
			return window.__iconifyLoading;
		}

		const cacheManager = {
			set: function (key, data) {
				try {
					localStorage.setItem(key, JSON.stringify({
						data: data,
						timestamp: Date.now()
					}));
				} catch {}
			},
			get: function (key) {
				try {
					const raw = localStorage.getItem(key);
					if (!raw) return null;
					const parsed = JSON.parse(raw);
					if (!parsed || !parsed.data) return null;
					if (Date.now() - (parsed.timestamp || 0) > CACHE_TTL) {
						localStorage.removeItem(key);
						return null;
					}
					return parsed.data;
				} catch {
					return null;
				}
			},
			remove: function (key) {
				try { localStorage.removeItem(key); } catch {}
			}
		};

		// IP 自动定位模式下没有 adcode/city，同样要缓存：
		// 否则每次翻页都会重新打一次接口，更容易撞上限流（缓存按访客各自的 localStorage 存）
		function getCacheKey(adcode, city) {
			if (adcode) return CACHE_KEY + "adcode_" + adcode;
			if (city) return CACHE_KEY + "city_" + city;
			return CACHE_KEY + "ip";
		}

		function fmt(value, suffix = "", fallback = "--") {
			if (value === null || value === undefined || value === "") return fallback;
			return `${value}${suffix}`;
		}

		// 当前容器配置的 UAPI key（为空表示只用访客额度）
		function getApiKey(container: HTMLElement): string {
			return (container && container.dataset.apiKey) || "";
		}

		// 单次请求：apiKey 为空走访客额度，非空走 key 额度
		async function requestWeather(
			adcode: string,
			city: string,
			extended: boolean,
			apiKey: string,
		): Promise<Response> {
			const params = new URLSearchParams();
			if (adcode) {
				params.set("adcode", adcode);
			} else if (city) {
				params.set("city", city);
			}
			if (extended) {
				params.set("extended", "true");
			}
			params.set("forecast", "true");

## 六、城市定位与接口参数

组件请求的是 UAPI 的天气接口：

```text
GET https://uapis.cn/api/v1/misc/weather
```

组件内部按下面的规则拼参数：

```js title="src/components/widget/Weather.astro"
const params = new URLSearchParams();
if (adcode) {
    params.set("adcode", adcode);
} else if (city) {
    params.set("city", city);
}
// 都没传时不带任何定位参数，交给接口按 IP 自动定位
if (extended) {
    params.set("extended", "true");
}
// forecast=true 才会返回最高/最低温、日出日落、降水概率
params.set("forecast", "true");
```

| 参数 | 说明 |
| --- | --- |
| `city` | 城市名，支持中文（`北京`）和英文（`Tokyo`），可选 |
| `adcode` | 行政区划代码（如 `110000`），优先级高于 `city`，可选 |
| `extended` | 返回扩展气象字段（体感温度、能见度、气压、紫外线、空气质量及污染物分项等） |
| `forecast` | 返回多天预报（最多 7 天），并附带当天最高/最低温、日出日落、降水概率 |

### 默认走 IP 自动定位

`city` 和 `adcode` 都不传时，接口会按访客客户端 IP 推导位置并查询天气。组件把这两个 prop 都设为可选，所以默认零配置就能用——访客在哪个城市，就显示哪个城市的天气。

### 想固定城市怎么办

如果希望无论访客在哪都显示你自己所在城市的天气，给组件设一个默认值即可：

```astro title="src/components/widget/Weather.astro" ins={1}
const { class: className, style, city = "青岛", adcode, extended = true } = Astro.props;
```

`adcode` 的优先级最高，想精确到区县时推荐直接填 `adcode`（例如青岛市崂山区为 `370212`）。

### 访客额度被限流怎么办

UAPI 的匿名额度是按出口 IP 动态限流的。同一网络下访问量一大（或者本地反复调试），接口就会开始返回 HTTP 429：

```json
{"details":"","error":"请求过于频繁，请稍后重试"}
```

值得注意的是，此时响应头里的 `X-Ratelimit-Remaining` 可能还显示上千次剩余额度——**剩余次数并不是限制因素，动态的 IP 限流才是**。所以「等一会儿再试」经常不管用（实测连续等待 5s / 20s / 30s / 60s / 90s 都没恢复），换 UA、加 Referer 也没有任何区别。

解决办法是去 [UAPI 控制台](https://uapis.cn/) 注册一个 Key，然后通过环境变量注入，让组件在被限流时兜底重试一次：

```bash
# .env.local（已被 .gitignore 忽略）
PUBLIC_UAPI_KEY=uapi-xxxxxxxxxxxxxxxx
```

组件的策略是**访客额度优先**：

```js
// requestWeather(adcode, city, extended, apiKey) —— apiKey 为空即匿名请求
let response = await requestWeather(adcode, city, extended, ""); // 先走访客额度
if (!response.ok && response.status === 429 && apiKey) {
    response = await requestWeather(adcode, city, extended, apiKey); // 只有被限流了才动 Key
}
```

这样正常访问时完全不消耗 Key 的额度，只有在匿名额度被限流时才用 Key 顶上。

**⚠️ Key 会暴露在前端。** 本站是纯静态站点，没有服务端可以代持密钥；`PUBLIC_` 前缀的变量会在构建时被内联进 HTML，任何人都能在页面源码里看到它。所以：

- 用**专门**的、可以在控制台随时吊销的 Key，并设置消费上限
- 不要提交到仓库（`.env.local`、`.dev.vars` 都已在 `.gitignore` 中）
- 在部署平台的环境变量里配置，而不是写进 `src/config`

## 七、实现要点

### 天气图标映射

接口返回的是数字图标码 `weather_icon`，组件用一张映射表把它翻译成 Material Symbols 图标名。

码值的权威来源是 uapis.cn 自己发布的 OpenAPI 规范：[https://uapis.cn/openapi.json](https://uapis.cn/openapi.json) 里 `weather_icon` 字段的 `enum` 与 `enumLabels`，一共 **443 个码值**。注意它用的是**和风天气「旧版」编码**，不是现在 QWeather 官网那份精简表，两者差异很大：

- `100`~`104` 晴/多云，`150`~`153` 是对应的**夜间**版本
- `300`s 雨（`350`/`351` 夜间）、`400`s 雪（`456`/`457` 夜间）
- `500`s 雾/霾/沙尘
- `800`s 是**月相**，不是云量
- `900`/`901` 热/冷
- `1001`+ 是各类预警（国内预警、水文地质、港澳、国际预警），数量最多

组件里逐个列举了 109 个常见码值，其余按区间回退：

```js

    "100": "material-symbols:sunny",
    "101": "material-symbols:cloud",
    "102": "material-symbols:partly-cloudy-day",
    "150": "material-symbols:clear-night",
    // ... 共 109 条
};

// 预警类码值数量庞大（1001-2554），未逐个列举的按区间回退到同类图标
function getWeatherAlertIcon(code) {
    const n = Number(code);
    if (n >= 1201 && n <= 1221) return "material-symbols:flood";      // 洪水 / 内涝 / 干旱
    if (n >= 1241 && n <= 1251) return "material-symbols:landslide";  // 地质灾害
    if (n >= 1000) return "material-symbols:warning";                 // 其余预警
    return null;
}

const getWeatherIcon = (code) =>
    weatherIcons[code] || getWeatherAlertIcon(code) || "material-symbols:cloud";
```

回退链是「精确映射 → 区间映射 → 通用图标」，三级都命中不到才会用到最后的 `material-symbols:cloud`，保证任何码值都有图可显示。

> 早期版本的映射表只有 16 条，其中 `200`~`210` 这 11 个码值在 uapis 的 443 个码值里**根本不存在**（`2000`s 是国际预警，不是风），并且 `"100"` 直接写成了 emoji `"☀️"` 而不是合法的图标名。现已按官方枚举重写。

### 缓存策略

所有定位模式的结果都会写进 `localStorage`，键名带上前缀，有效期 30 分钟：

```js
const CACHE_KEY = "weather_data_cache";
const CACHE_DURATION = 30 * 60 * 1000; // 30 分钟
```

这里有个刻意的设计改动：**adcode、city、IP 定位三种模式的结果都会缓存 30 分钟**。早期版本为了「访客切换网络后 IP 变了会显示错误城市」只缓存指定城市，但实测发现 IP 模式下每次翻页都会重新打一次接口，反而更容易撞上平台的动态限流，所以现在统一缓存；想要立刻刷新，点「重试」按钮会先清掉对应缓存再重新请求。

### 扩展信息与日出日落

扩展字段（体感温度、能见度、气压、紫外线、云量、降水量）直接取响应里的同名字段；日出日落和降水概率则来自 `forecast` 数组的第一项：

```js
const todayForecast = data.forecast?.[0] ?? null;
setData("[data-sunrise]", todayForecast?.sunrise || "--:--");
setData("[data-sunset]", todayForecast?.sunset || "--:--");
setData("[data-pop]", todayForecast?.pop != null ? `${todayForecast.pop}%` : "--%");
```

所有取值都做了空值兜底，字段缺失时显示 `--`，不会因为某个城市数据源不全而报错。

### 空气质量配色

AQI 等级 `aqi_level` 为 1~6，组件把它归成三档配色：优/良为绿色、轻度及以上为黄色、再往上为红色，一眼就能看出空气好坏。

### 三态 UI 与错误重试

组件用 `data-*` 属性配合一个 `updateUI()` 统一管理加载、错误、内容三种状态；请求失败时展示错误信息与「重试」按钮，不会白屏。

### 主题适配

温度、标签等文字统一走 `text-neutral-900 dark:text-neutral-100`，图标颜色用主题变量 `--primary`，暗色模式下单独调整了数字颜色与悬浮阴影，保证两种主题下都清晰可读。
